# Evon · 最小化 SWE-Agent（TypeScript）

这是一个逐步构建的编程代理原型，已接通真实模型 API 和“模型 → 工具 → 结果回填 → 模型”的主循环。支持流式输出、连续对话、Ctrl+C 打断，以及目录浏览、代码检索、文件读写、局部编辑和 shell 命令执行。

## 启动

需要 Node.js 24+。代码检索工具 `grep` 和文件检索工具 `find_files` 还需要本机安装 ripgrep，并确保 `rg` 位于 `PATH` 中（可通过 `rg --version` 检查）；`run_bash` 的命令执行与测试转义适用于 macOS/Linux。项目直接运行 TypeScript；安装依赖后即可启动、测试和检查类型。

```bash
npm install
```

首次使用时复制配置模板：

```bash
cp .env.example .env
```

编辑 `.env`，填写以下配置：

| 变量 | 用途 |
| --- | --- |
| `BASE_URL` | 模型服务的 API 基础地址 |
| `API_KEY` | 模型服务的访问密钥 |
| `MODEL` | 实际调用的模型 ID |

当前模型适配器使用 Responses API，模型服务需支持流式输出和函数工具调用。

直接启动交互会话，或在启动时传入第一个任务：

```bash
npm start
npm start -- "阅读当前项目，说明它的结构"
```

运行时会显示步骤编号、模型逐步生成的文本和工具调用状态。任务完成后回到 `evon >` 提示符，可继续追问；同一进程内会保留对话上下文。

| 输入或操作 | 行为 |
| --- | --- |
| 普通文本 | 发起任务或继续追问 |
| `/clear` | 清空当前对话上下文 |
| `/exit` 或 `/quit` | 退出程序 |
| 任务执行中按 Ctrl+C | 取消当前任务，随后可继续输入 |
| 等待输入时按 Ctrl+C | 退出程序 |

当前会话保存在内存中，退出程序后不会保留。启动目录即工作区；`ls`、`grep` 和文件工具会校验操作路径的工作区范围，`run_bash` 以当前进程权限执行 shell 命令，尚无进程沙盒。

```text
src/
├── index.ts             # CLI 入口：初始任务、REPL、会话命令与中断
├── agent.ts             # 主循环：模型 → 工具 → 结果回填 → 模型
├── llm.ts               # Responses API 适配与流式事件处理

├── types.ts             # 对话消息、工具调用的类型
├── tools/               # 每个原子工具单独存放
│   ├── index.ts         # 统一导出和工具分发
│   ├── ls.ts            # 浏览目录的直接子项
│   ├── grep.ts          # spawn 执行 rg，逐行解析 JSON 匹配
│   ├── find-files.ts    # spawn 执行 rg，按 glob 查找文件路径
│   ├── run-bash.ts      # 执行 shell 命令
│   ├── read-file.ts     # 分页读取文件
│   ├── write-file.ts    # 创建或完整覆盖文件
│   └── edit-file.ts     # 局部修改文件
└── utils/
    ├── format-diff.ts   # diff 终端配色与纯文本回退
    ├── path.ts          # 工作区路径校验
    └── truncate.ts      # 按行数与 UTF-8 字节数截断输出
```

## 工具行为

`ls` 列出目录的直接子项，包含隐藏文件，按名称排序，每行一项，目录名后加 `/`。使用 `path: "."` 浏览工作区根目录；`limit` 省略或为 `null` 时默认展示前 100 项，必须为正整数。超出数量限制时提示剩余项数，输出正文超过 50KiB 时保留头部并附加截断提示；空目录返回 `(空目录)`。

`grep` 借鉴 pi，直接通过 `spawn` 执行本机 `rg --json`，用参数数组传入搜索条件，并逐行解析匹配事件。支持单文件和目录递归搜索，默认遵循 `.gitignore`，跳过隐藏文件和二进制文件，不跟随目录遍历中的符号链接；显式指定文件及 glob 时使用 `rg` 的过滤规则。搜索路径会校验工作区范围及符号链接的实际目标。

参数为 `{ pattern, path, glob, literal, ignoreCase, limit }`：`pattern` 是必填的正则或普通文本；`path` 默认 `"."`，`glob` 默认不过滤，`literal` 和 `ignoreCase` 默认 `false`，`limit` 默认 `100` 且必须为正整数。可选参数省略或为 `null` 时采用默认值。例如：

```json
{"pattern":"runAgent","path":"src","glob":"*.ts","literal":true,"ignoreCase":false,"limit":100}
```

结果按路径排序，每条为 `工作区相对路径:行号:内容`，行号从 1 开始。无匹配返回 `(无匹配)`；非法正则、缺失 `rg`、超时和取消会返回工具错误。搜索超时为 30 秒，取消或超时会终止子进程。超长匹配正文保留前 500 字符并附加提示，路径和行号单独保留，可用 `read_file` 查看完整内容。

`limit` 控制所有文件合计的匹配行数，达到上限后立即终止 `rg` 并提示。结果恰好等于上限时也会提示，表示已达到限制，不代表已确认还有更多匹配。收集到的结果正文再按 50KiB 保留头部并附加截断提示，不另设 2000 行上限。

`find_files` 按 glob 递归查找文件，通过 `spawn` 执行 `rg --files --null`，流式解析 NUL 分隔的路径后筛选，不会因匹配 glob 而重新包含被忽略的文件。默认遵循 `.gitignore` 等忽略规则，跳过隐藏文件，不跟随遍历中的符号链接。

参数为 `{ pattern, path, limit }`：`pattern` 必填且非空，例如 `*.ts`、`**/*.test.ts`；不含 `/` 时匹配任意层级的文件名，包含 `/` 时相对于搜索目录匹配。`path` 默认为 `"."`，必须是工作区内的目录，并校验符号链接的实际目标；`limit` 默认为 `100`，必须为正整数。可选参数省略或为 `null` 时采用默认值。

结果按路径排序，每行一个工作区相对路径；无匹配返回 `(无匹配)`。达到数量上限后终止搜索并提示，文件数恰好等于上限时也会提示。搜索超时为 30 秒，取消或超时会终止子进程；异常退出时回填退出码和 stderr 中的错误原因。

为准确检查输出和状态，测试约定 `runBash` 返回 JSON 字符串，例如：

```json
{"stdout":"hello\n","stderr":"","exitCode":0,"timedOut":false}
```

- 正常完成：`exitCode` 为 `0`；即使有 stderr 输出也不代表失败。
- 非零退出：返回实际退出码，同时保留 stdout 和 stderr，不直接抛出命令执行错误。
- 超时：`timedOut` 为 `true`，`exitCode` 为 `null`，保留超时前已收集的两种输出。

模型调用 `run_bash` 的超时为 30 秒。回填时，stdout 和 stderr 的正文各自保留末尾最多 2000 行或 50KiB，超出时附加截断提示。

`read_file` 按 UTF-8 返回文件原文，不添加行号；空文件返回空字符串，未截断时保留原有换行。支持 `offset`（从 1 开始的起始行号）和 `limit`（读取行数）；省略或传 `null` 时分别表示从第 1 行开始、读取到文件末尾。选取的正文超过 2000 行或 50KiB 时保留头部并附加截断提示，可通过分页继续读取。

`writeFile(path, content)` 按 UTF-8 原样写入完整内容：文件不存在时创建，已存在时完整覆盖，空内容会创建空文件或清空已有文件。父目录必须已存在，不自动创建目录。对应工具名为 `write_file`，参数为 `{ path, content }`；文件系统错误由 `executeTool` 转换成“工具执行失败”结果。

`editFile` 只局部修改已有文件：`oldStr` 必须非空，按精确匹配、CRLF/LF 换行容错、行尾空格和 Tab 容错逐级查找，并要求在当前级别恰好匹配一次；缩进与行内空白仍需一致。`newStr` 按原样写入，也可以为空以删除内容。空旧文本、零匹配、多次或重叠匹配，以及替换前后相同，都会返回“文件未修改”提示并保留原文件；文件系统错误由 `executeTool` 转换成“工具执行失败”结果。创建文件或整文件重写使用 `writeFile`。

修改成功后返回包含行号和前后各三行上下文的纯文本 diff，正文超过 2000 行或 50KiB 时截断，实际文件完整写入。交互终端将新增行显示为绿色、删除行显示为红色，文件信息与差异块行号显示为灰色；设置非空的 `NO_COLOR`（例如 `NO_COLOR=1 npm start`）、`TERM=dumb`，或输出到管道/文件等非交互终端时，显示纯文本。颜色仅用于终端展示，回填给模型的工具结果保持纯文本。
